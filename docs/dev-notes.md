### 動かして確認する方法

1. DB: `api` ディレクトリで `docker compose up -d --wait`
2. api: `api` ディレクトリで `bun run dev`(ポート 3001)。`api/.env` を変えたら、api を再起動する
3. web: `web` ディレクトリで `npm run dev`(ポート 3000)
4. `http://localhost:3000/` を開く

実際にログインするには、`api/.env` に `GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`、`GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` が必要。未設定だと、ボタンを押しても、api が「プロバイダが見つかりません」を返す(画面の見た目の確認には、影響しない)。

## 認証まわり

- GitHub と Google の OAuth アプリの登録と、クライアント ID・シークレットの設定、コールバックの動作確認は、別の担当。未設定の間は、実際のログインは動かない。
- `api` の認証(better-auth)は、`user`、`session`、`account`、`verification` の 4 つのテーブルを使う。アプリ側の `users` とは別(統一は [v2-todo.md](./v2-todo.md) を参照)。

## 招待の画面(`web/`)

- プロダクト画面のリーダーにだけ「メンバーを招待」を出す。入力は 1 欄で、`@` を含み先頭が `@` でなければメール、それ以外は GitHub のユーザー名として送る。
- ホームに、自分宛ての保留中の招待(承認・拒否)を出す。0 件ならセクションごと出さない。見た目は暫定(ターミナル風)で、Figma ができたら入れ替える。

## タスクの作成と編集の画面(`web/`)

- プロダクト画面のリーダーにだけ「タスクを追加」を出し、ツリーのタスク名を押すと編集のモーダルが開く(メンバーには押せない)。ツリーには完了済みのタスクが出ないので、編集できないタスクはない(確認から保存までの間に完了すると、api の 409 の文が `ERR …` で出る)。
- 期限は日本時間(+09:00)として入力・送信する。編集で期限や説明を空にすると、null / 空文字で送って消す。担当者は編集では変えられない。種類は、api に外す手段がないので、すでに種類があるタスクでは「なし」を出さない。
- カードに出るのは 3 件までで、4 件目以降は、カード下の「他 N 件」(全員が押せる)で開く一覧のモーダルから見る。リーダーは一覧のタスク名を押すと、一覧を閉じて編集のモーダルが開く(閉じても一覧には戻らない)。

## テスト

- `api` のテストは、`bun test`(`api` ディレクトリ)で全体を実行できる。`bunfig.toml` の事前設定(`tests/setup.ts`)で、外部認証の環境変数と `NODE_ENV` をそろえている。テストファイルを足したあとは、全体の実行で確認する。
- **既知の問題**: `bun test --randomize`(テストの順序をランダムにする)にすると、タスク追加・変更の NUL 文字のテストが、シードによって落ちる。テストの前提が、順序に依存している。通常の順序では通る。
