## 追加した機能

- **ツリーの複数選択と、まとめて動かす・削除**(#292、#301)
  - **選び方**: カード・セクション・メモを、Shift で追加・解除して選ぶ。背景のドラッグで範囲選択(触れたものを選ぶ)。`Esc` で取り消す
  - **パン**: Space を押しながらのドラッグ、中ボタンのドラッグで、キャンバスを動かす(中ボタンの自動スクロールは止めた)
  - **まとめて動かす**: 2 つ以上を選んでドラッグすると、選んだものが同じ差分で動く(所属は変えず、位置だけ)。4px 動くまではクリック扱い。`Esc` で元に戻す。動かせるのは、カード・セクション・自分が変更できるメモ。セクションを選ぶと、所属するカードも一緒に動く
  - **まとめて削除**: 2 つ以上を選んで `Delete` / `Backspace` を押すと、確認なしで削除する(元に戻せない)。消せるのは、セクション(リーダーのみ)と、自分が変更できるメモ。カードは消さない
- **タスクのやり取りに、報告・差し戻し・承認のログ**(#305)
  - **ログに残る**: 完了報告・再提出・差し戻し・承認が、やり取りの履歴に残る(誰が、いつ、何を)。完了報告と差し戻しには、本文を付けられる(報告は任意、差し戻しは必須。2000 字まで)
  - **差し戻し**: リーダーが、確認待ちのタスクを、理由を付けて担当者へ戻せる(状態は `rejected`)。担当者にメールで知らせる。報告・差し戻し・承認のメールには、本文の先頭を添える
  - **編集・削除**: 自分のメッセージを、編集・削除できる(削除は、「削除されました」の行が残る)
  - **確認待ちの判定**: 日時(`reportedAt`)からの推測をやめ、状態(`status === 'reported'`)に統一した
- **メッセージへのリアクション**(#306): 👍 🎉 👀 ✅ ❓ の 5 つ。押せるのは、コメントを書ける人(リーダーと担当者)だけ。もう一度押すと外れる。コメントだけでなく、報告・差し戻し・承認の行にも付けられる。完了済みのタスクと、削除済みのメッセージには付けられない
- **確認待ちの赤い点**(#299): 確認待ちのタスクがあるプロダクトに、サイドバーの行と、たたんだ帯のアイコンに、赤い点を出す(リーダーのプロダクトだけ。1 分おきに更新)
- **たたんだサイドバーに、プロダクトのアイコン**(#297): 押すと、そのプロダクトへ移動できる。画像がなければ、名前の頭文字の丸を出す

## API の変更

- `POST /api/product/:productId/delete-selection`(新規。リーダーのみ): セクション・メモを、まとめて **soft delete**(`deleted_at` を入れる。10 分は行が残る)。**画面は、まだ呼んでいない**(画面の複数削除は、既存の 1 件ずつの `DELETE` を順に呼ぶので、すぐ消える)。戻す API は、まだない
- `POST /api/product/:productId/move`(新規): カード・セクション・メモを、まとめて動かす(1 つでも失敗したら、全部反映しない)
- soft delete 中のセクション・メモは、一覧・更新・削除・移動・所属から、見つからない扱い(404 / 422)。`deleted_at` は、応答に出さない(#309)
- `POST …/task/:taskId/reject`(新規。リーダーのみ・本文必須): 差し戻し
- `POST …/task/:taskId/complete-report` が、本文(任意)を受け取る。`PATCH …/complete` は、承認のログを残す
- `POST` / `DELETE …/message/:messageId/reaction`(新規): リアクション。`GET …/message` の各行に、`reactions`・`canEdit`・`canDelete` が付く
- `GET /api/product`(プロダクト一覧)に `pendingReviewCount`(リーダーのプロダクトだけ。メンバーは `null`)、ツリーのタスクに `status` が付く

## 本番への反映

- DB(`migrate` で適用):
  - `sections`・`product_notes` に、`deleted_at` を追加した(`20261120031614_soft_delete_selection`)
  - `task_message_reactions` の表を追加した(`20261119043403_add_task_message_reactions`)
- 定期実行: `wrangler.jsonc` の `triggers.crons` に、`*/5 * * * *` を追加した。5 分おきに、期限(10 分)を過ぎた soft delete の行を、物理削除する(これまで、本番では動いていなかった)。毎日 18:00 UTC の、文書の自動削除は、そのまま。デプロイ後に、Worker のログ(`[soft-delete] …`)で動作を確かめる
- 設定・R2 の追加は、ない
